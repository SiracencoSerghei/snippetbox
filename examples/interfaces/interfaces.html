Go Interfaces — Simple Mental Model

Interface = contract
If a type has required methods → it automatically satisfies the interface.

Shape Interface Example (Your Case)

type Shape interface {
    Area() float64
}
Any type that has Area() float64 automatically becomes a Shape.

Implementations

type Circle struct { radius float64 }
type Square struct { length float64 }
type Triangle struct { base, height float64 }

func (c Circle) Area() float64 {
    return 3.14 * c.radius * c.radius
}

func (s Square) Area() float64 {
    return s.length * s.length
}

func (t Triangle) Area() float64 {
    return 0.5 * t.base * t.height
}
"Why multiple Area() functions?"

Because each struct has its own implementation.
Same method name → different behavior (polymorphism).

Using Interface

func calculateArea(shapes []Shape) {
    for _, s := range shapes {
        fmt.Println(s.Area())
    }
}
Go doesn't care what the actual type is.
It only cares: "does it have Area()?"

Main Function

func main() {
    c := Circle{radius: 5}
    s := Square{length: 6}
    t := Triangle{base: 6, height: 8}

    shapes := []Shape{c, s, t}
    calculateArea(shapes)
}

What Actually Happens

At runtime:
- Go stores (type + value) inside interface
- Calls correct Area() dynamically

Circle → Circle.Area()
Square → Square.Area()
Triangle → Triangle.Area()

Key Insight

You are NOT redefining the same function.
You are attaching methods to DIFFERENT types.

Common Beginner Mistake

Thinking interface "forces implementation" ❌
In Go:
Types implement interfaces implicitly ✅

Mental Model

  • Interface = behavior
  • Struct = data
  • Method = action
  • Same method name ≠ same function

How Interface Works Internally

Execution Flow

    for _, shape := range shapes {
        shape.Area()
    }
Step-by-step:

1. Take interface value
2. Read its TYPE
3. Find method for that TYPE
4. Execute correct implementation
